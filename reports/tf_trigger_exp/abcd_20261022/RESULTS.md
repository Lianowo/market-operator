## 3. 为什么全灭:dev/test 的符号翻转(归因,非判定)

基线与本脚本 a0 的 event×regime 分解(dev / full 皆实测,test = full−dev):

| 单元 | dev | full | 推得 test |
|------|-----|------|-----------|
| E1(ACCEPT)×TRANSITION | 80 笔 **−4.96** | 108 笔 **−46.22** | 28 笔 −41.3 |
| E3(REJECT)×TRANSITION | 281 笔 **−112.71** | 403 笔 **+20.47** | 122 笔 **+133.2** |
| 12h 全族 | 236 笔 **−71.9** | 全段 **+5.7** | **+77.6** |

- 臂 A 只动 ACCEPT×TRANSITION(dev 仅 −5),所以 dev 几乎无差异;1.5x 下
  反而把 12h 的仓位构成改了 → −35.5。
- 臂 B 的收益在 dev 里看起来是 12h 的 −71.9 被删掉,但 12h 在 test 是 **+48.1**,
  于是一删就还回去 −51.2。
- **我上一轮结论里"ACCEPT×TRANSITION −46.2""12h 是容量黑洞"两条,都是
  full/ dev 混合口径造成的错觉**:−46.2 是全段数,其中 −41.3 落在 test;
  12h 全段仅 +5.7,dev 的 −71.9 被 test 的 +77.6 抵掉。真正的亏钱单元是
  **dev 段的 E3×TRANSITION(−112.7)**,而它在 test 是 +133.2 —— 即
  "TRANSITION 是负 regime" 这一条**不成立**,只是 dev 段现象。

## 4. 分臂机制(逐臂单变量,不组合)

**A(ACCEPT×TRANSITION 禁入)= 无效**。dev 只挡掉 49 笔 E1 事件,
`2h 55.7→45.3 / 1d 17.1→28.5` 互抵;1.5x 下更差。代码事实:canonical id
是 **E1/E3**(`canonical_event_id("ACCEPT")=="E1"`),上一轮"E1≡ACCEPT"仍成立,
但按族过滤必须用 E 名。

**B(12h 0.0225→0.0075,4h→0.0375)≈ "关掉 12h"**。0.0075×300=2.25 USDT
< 单笔候选最坏情景(2.25 风险 + 双边费 ≈ 2.58)⇒ 12h **不是 1 槽而是 0 槽**
(12h N=0)。预注册写的"3 槽→1 槽"与实测不符,属参数刻度错误(若要 1 槽需
≥0.0086)。分解诊断(dev-only):B12 单独 +100.7、B4 单独 **+22.4(比基线差)**、
B 合并 +112.5 ⇒ 4h 扩容单独是负贡献(B4 里 12h 反而从 236 笔/−71.9 恶化到
243 笔/−92.4),靠"释放 12h"才转正,存在 TF 间挤出效应
(同一 `_available_entry_notional` 全局名义/杠杆口径)。

**C(REJECT 前缘 maker)= 强负**。引擎计数(dev):`reject_front_limit=1157`
条决策转限价,`limits_armed=1102`,`limit_fills_entry=141`(12.8%)、
`limit_expired=694`(63%)、`limit_min_size_skips=492`、`e1_priority_cancels=265`
(同战役 E1 事件触发**优先级撤单**,把 REJECT 挂单直接撤掉)。成交后 wr 21.1%、
PF 0.41、DD 93%,N 816→298。机制清楚:前缘限价只在"价格回到边缘"时成交,
恰好筛出继续反向的那批;`zone 前缘` 到 `invalid(结构外缘∓k_bm·ATR)` 的距离
只剩 ~0.1 ATR,止损极紧 ⇒ 高频小亏 + 少数大亏。上一轮"maker 省 47.7 USDT
(+17%)"的估算假设是**收盘价挂 maker**,不是前缘回踩,两者不可互推。

**D(冻结净敞口 cap)= 唯一在 test 两侧都不显著变差的臂**。full +42.6(@1.5x
+22.7),DD +2.74pp;dev 收益主要来自 12h 容量释放(−71.9→−37.6),
test 里 12h 几乎不变(48.1→48.6),代价是 1d 22.6→5.8。容量计数印证:
`portfolio_cap_skips` dev 217→128、`opens_filled` 816→817、
`min_size_skips` 61→111(容量放开后更多单撞到最小手数)。test@1.5x 恰好
打平(+0.4)⇒ T2 过、T1 不过。
