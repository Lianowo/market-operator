## 2. P1 —— 有明确机制、可立即立项

### B1 per-symbol 跨 TF 风险池(crowd 直接指向的唯一"真抢占") — ❌ 否决(2026-10-24)
- **证据**:同币跨尺度同时持仓占全部持仓时长 **53.7%**(1696 对、5.6 万/10.4 万小时;
  放开容量后 63.7%)。一次 4% 下跌同时打掉 BTC 的 2h/4h/12h/1d 四个止损 =
  4×0.75% = **3% 权益**。而 `BudgetPools`(`capacity.py:103`)只有 `portfolio_frac` +
  `per_timeframe_frac`,**没有 symbol 级池** ⇒ 这个风险现在完全没上限。
- **做法**:`pools()` 增加 `("symbol", frac, None)` 作用域(按 `campaign_key.split("@")[0]` 聚合),
  config `"symbol_cap_frac": 0.015`(≈2 笔)。
- **判定**:不看 E[R] 单值,看 **MaxDD / Calmar / 相关性调整后收益**;
  预期净额下降 5–10% 但 DD 降 20%+,`A5 隔离性`要放宽为非目标 TF 净额 ≥ −15%。
- **注意**:这是"风险预算实验",不是因子实验(tf_solo §7 的纪律)。
- **❌ 实测(relative to base_hist)**:3% 池 −219.83(DD 28.97→23.37,**E[R] 0.1228→0.1212**);
  4.5% 池 −16.83(DD 28.42)。**被砍掉的交易与留下的交易质量相同** ⇒ 上限只筛出数量、
  没筛出风险;按本项自己的判定门(净额降 5–10% / DD 降 20%+)不达标。**不做**。

### B2 慢周期保底并发 / 按持仓时长计费 — ❌ 否决(2026-10-24)
- **证据**:1d 的 `TF_CAP` 压制最重(129 次)、12h 574 次;1d 持仓 252h ⇒ 周期池被
  "占着不放"。`tf_solo` §7 第 2 条已把这条写成纪律:**12h/1d 的改动只能按"预算实验"立项**。
- **做法**:`tf_cap_by_tf` 改为 `{"1d": {"frac":0.0225, "floor_slots":1}}` 或引入
  `budget_cost = frac × (hold_hours/24)` 的时长计费。
- **判定**:`portfolio_cap_skips` 必须同时报(否则无法区分"没信号"与"没预算")。
- **❌ 实测(relative to base_hist)**:预留 0.75% / 1.5% / 2.25%(12h+1d 各一份)
  ⇒ 净额 **−412.59 / −489.30 / −463.72**,n 1217/797/565。全档位崩塌不是参数问题:
  预留语义 = 对 2h/4h 的**持续税率**(0.75%+0.75% 常驻缺席≈4.5 USDT,而 2h 单笔风险
  仅 0.0075×300≈2.25 USDT)。**若要重开,只能改成"只慢周期可用的硬 floor_slots"**,
  不能用额度预留;且 `tf_cap_by_tf` 已经把"慢周期被挤"这件事解决了。

### B3 `capacity_mode` 在真实资金费口径下重测

- **做法**:A1 落地后重跑三档;若顺序不变才算"承重",若翻转则**现行模式的选择也要重写**。

### C3 12h 退役 vs 并入 4h 的**结构性**对照 — ❌ 否决退役(2026-10-24)
- **现状**:12h 的证据是三重否(入场闸 do-nothing 最优、出口 ≤0、原始漂移 −0.16 ATR),
  但"负期望"这一条建立在**错的资金费模型**上(真实口径 +0.0206)。
- **做法**:三臂 `a0` / `no_12h` / `12h→4h 并档`(把 12h 的事件路由到 4h 帧),
  在 A1 + A5 口径下一次性判定。**这是配置/结构性选择,不是调参,不违反"不按 dev 调参"纪律。**
- **判定**:以 E[R] **和** DD 双指标;12h 只有"边际贡献 > 0 且 DD 不恶化"才留。
- **❌ 实测**:`no_12h`(hist)净额 **−214.05**(12h 自身 +201.11;腾出预算使 2h +14、
  1d +14、4h −41),DD 28.97→26.11(`const` 下 −299.96)。**12h 是第二大贡献周期 ⇒ 保留**。
  "12h 负期望"来自错的资金费模型;但 §A1 的 dev 段显示 12h 在 dev 上反而 −19.88,
  即"翻正"是**分段依赖**的,不能当作稳定结论。

### C1 目标距离**上界**(config 不可表达) — ⚠️ 已实现,数值否决(2026-10-24)
- **问题**:OPTPATH §8 明列局限——只有 `min_box_rr` 下限,没有 `max_target_r`;
  而 1d 候选的收益恰恰来自"目标从 opposite 改 mid"(=缩短目标距离)。
- **证据**:QUALITY §2 的 20×TF 网格里,1d 毛 +0.266 已**贴上 k=1 几何上限 +0.274**;
  目标太远 ⇒ 名义/风险大 ⇒ 费率与滑点按 R 计翻倍。
- **做法**:`V6Params` 加 `max_target_r`(默认 `inf` ⇒ parity),A/B 在 1d/12h 上各测一套。
- **预期**:这是**唯一一个"降成本"仍然有效**的方向(因为与资金费口径无关)。
- **⚠️ 实测**:`RouterParams.max_target_r` 已实现(默认 `None` ⇒ 逐位不变,`target_r_clamped`
  计数器可观测)。**4R:净额 −164.21**(截断 182 次;4h −40、12h −84、1d −35),
  DD 反升到 33.95% ⇒ 截断剪掉右尾。**8R:与 base 逐位相同**(0 次触发)⇒ 只能记作
  "未来目标更远时的免费上界",**不得声称有任何改善**。预期中的"降成本"没有出现,
  因为名义/风险由止损与目标共同决定,目标截断反而降低了 R 分母的稳定性。

### C2 限价入场(maker)降费 —— 12h/1d
- **证据**:名义/风险 12h **25.4×**、1d **19.5×**;taker 6bp vs maker 2bp ⇒ 每边省 4bp,
  折成 R 是 12h 0.010R/边、1d 0.008R/边;而 12h 的净 E[R] 只有 +0.021(真实口径)。
- **可行性**:`broker.py` **已有** `RestingLimitOrder` 与 `_arm_reduce_limit` 通道。
- **未知(必须先测)**:漏单率与逆向选择。1d 的目标距离大 ⇒ 回抽到限价的概率高;
  但 2h 的动量入场可能等不到回抽。**先做一个纯测量:`entry_limit_by_tf` 下的 fill 率与
  "成交者 vs 未成交者"的事后毛 R 差**(若未成交者更差 ⇒ 限价是免费筛选)。

### C5 "到 +1R 后限时"时间帽(长周期专用)
- **证据**:MEMO §4:MFE 在 **~3 根 TF bar 内**出现;WHY_12H_1D:到过 +1R 只捕获

### F4 bootstrap 口径 — ✅ 已实现(2026-10-24)
- 现有 CI 是**逐笔** bootstrap;但持仓重叠(53.7% 同币跨 TF)+ 时间聚集 ⇒ 独立同分布假设破了。
- 做法:块 bootstrap(按周/按事件簇)。预期 CI 会**变宽** ⇒ 部分"显著"会消失。
  这是**减法**工作,但对所有后续判定都是地基。
- **✅ 落地(2026-10-24)**:circular block bootstrap(按平仓日聚合、块长 5 天、2000 次)。

  `P=0.154` ⇒ **优势仍未显著**。口径限制:只重排已实现盈亏,不重建权益路径(无复利/无容量
  反馈),故 CI 比"换一段行情重跑"窄,只可用于符号稳定性。

### F5 参数邻域的稳健性(代替 dev-max) — ✅ 已实现(2026-10-24)
- 119 格显示 dev 最优的 OOS 税极大;若改用"邻域均值最大化"(即选**平台**而非**尖峰**),
