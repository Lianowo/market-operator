# 每尺度最优路径 + 四尺度最优组合（2026-10-23）

**问题（两问）**
1. 先给 2h / 4h / 12h / 1d **各自**找一条路径,使该尺度下的胜率、盈亏比、净 R 同时
   达到它能达到的最好水平;
2. 四个尺度各自最优之后,再找**最优组合**。

**性质**：只读诊断。不改 `config/`、不改 `src/`、不产生裁决结论、不消费 virgin 样本。
全部数字由 `scripts/_diag_v21_tf_opt.py` 复现。

---

## 0. 方法：为什么"先单尺度、后组合"，以及三指标怎么降维

### 0.1 必须先单尺度

`reports/tf_solo_20261023/RESULTS.md` §4/§9 记录过：组合链里同一尺度的净额与独占账户时不同
（12h 在组合链里 net@1.5 = −21.5，独占账户时 +45.0）。但**这不是"抢槽"**——`--stage crowd`
（§5.5）实测：全部 `cap_skips` 都是 `TF_CAP`，`PORTFOLIO_CAP` 恒为 0；四尺度并发峰值 13 个、
**每尺度 4 个，与独占账户时完全一样**。真正的耦合是**共享权益**：`risk_usdt = risk_frac × 权益`，
同一笔交易在两条权益路径下差 27%~50%，而 E[R] = Σnet/Σrisk 是按风险加权的。

所以：

- **单尺度搜索** = 该 TF 独占 300U 账户（`tf_cap_by_tf` 全 0.0225 只服务它）；
  度量"这个尺度本身的边缘"在**单一权益路径**下的值。
- **组合阶段**再单独度量"进入共享账户后这个边缘变成多少"——并明确这是权益路径/加权效应，
  不是槽位竞争（§5.5）。

### 0.2 搜索空间（全部是 config 里**已存在**的字段，不改 src）

| 维度 | 字段（per-TF，`router_params_by_tf`） | 语义 |
|---|---|---|
| 入场闸 | `min_box_rotations` / `min_box_quality` / `min_bar_impulse_atr` / `zone_cooldown_bars` | 箱体旋转次数 / 质量分 / 触发 bar 冲动 / 同沿冷却 |
| 出口几何 | `k_is` / `turtle_stop_atr` / `reject_target_mode` / `reject_use_struct_stop` | 失效距离下限 / 初始防线 / 目标（无·箱体中点·对侧缘） / 结构止损 |

**重要**：这 8 个字段全部 per-TF 可配 ⇒ 本报告选出的"单尺度最优路径"**可以直接写进
config 并参与组合**，不需要任何全局开关（TP / BE / 时间止损那类全局开关不在候选内，
见 §4）。

搜索：R1 粗网格 4×3×2×2 = 48 格 → R2 逐维细化（+35）→ R3 出口全因子 3×3×3×2 = 36 格
= **每 TF 119 格**，单格回放 ~0.5s（帧预建后）。

### 0.3 三指标先降维（这一步很关键）

用户要的"胜率 + 盈亏比 + 净 R"里，前两个不是两个自由度：

```
PF = (WR · avgWin) / ((1−WR) · avgLoss) = WR/(1−WR) · payoff
```

即 **WR 与 payoff 一经确定，PF 就确定**；不存在"同时把胜率和盈亏比都推高"的独立
目标——那是同一个点的两种坐标（提高 WR 必然压低 payoff，反之亦然）。
真正的两个独立轴是：

- **轴 A：PF（= WR×payoff 的组合）** —— 出场几何/入场质量决定；
- **轴 B：净 E[R] = Σnet / Σrisk** —— 再叠加成本地板与 R 定义（`risk_atr`）。

所以下面每张表都给 `E[R] / WR / payoff / N`，读者自己就能读 PF；判定一律用 E[R]
（唯一与"最后净 R"直接对齐的量）。

### 0.4 选择纪律

- **只在 dev 段选**（dev = 2024-10→2026-03，502d），test 段只用于报告；
- 约束 `N ≥ 50% 基线 N`（否则"只做 5 笔"也能赢 E[R]）；
- 另报 **top-10 dev 格在 test 上的中位数** ⇒ 量化"选择乐观度"（§3）。

### 1.2 1.5× 那一列必须用"同一交易集"读（方法学修正）

两个成本档的回放会走上不同的账户路径（复利 → `risk_usdt` → 最小下单量 / 仓位上限），
所以 **1.0× 与 1.5× 不是同一批交易**：

| TF | 臂 | 笔数 1.0× / 1.5× | 交集 | 重叠率 |
|---|---|---|---|---|
| 2h | base / best | 629/626 · 595/595 | 617 · 588 | 98% · 99% |
| 4h | base / best | 331/330 · 366/363 | 330 · 355 | 100% · 97% |
| 12h | base / best | 348/340 · 354/349 | 290 · 304 | **83% · 86%** |
| 1d | base / best | 128/134 · 147/145 | 117 · 143 | 91% · 97% |

关键在于 **1d 那 11 笔不重叠的交易几乎贡献了全部毛利**：基线 1d 在 117 笔交集上的
gross E[R] 只有 **+0.052**，而全体 128 笔是 **+0.251**。⇒ 成本档之间直接横比，
测到的主要是"这一档恰好抽掉了哪几笔大的"，不是成本本身。

所以一律改用**同集反事实**：以 1.0× 的交易集为基准，把成本乘数换成 m
（`net(m) = gross − m·c`，成本对 m 线性），这才是成本结构本身的效果。

| TF | Δgross | cost/R @1.0× | 成本占毛利 | 同集差 @1.0× | 同集差 @1.5× | 盈亏平衡 m* | 实测差 @1.5× |
|---|---|---|---|---|---|---|---|
| 2h | **+0.017** | 0.074→0.068 | 62%→50% | +0.023 | +0.026 | 任意 m 都更好\* | +0.012 |
| 4h | +0.024 | 0.064→**0.089** | 24%→30% | −0.001 | **−0.014** | 0.95×（成本要降才划算） | −0.014 |
| 12h | −0.020 | 0.064→0.059 | 30%→31% | −0.016 | −0.013 | 4.42×（不可达） | −0.029 |
| 1d | −0.045 | 0.074→**0.039** | **30%→19%** | −0.010 | **+0.007** | **1.29×** | +0.171 |

\* 2h 的格子毛利更高、成本也更低，但它多出来的钱全在 dev 段（test +0.008→+0.001），
所以仍然"不可用"。2h/4h 两档重叠 97–100%，它们的 1.5× 横比是干净的；12h/1d 不是。

**这张表把"1d 在 1.5× 反超 +0.171R"降级为 +0.007R**：差额几乎全部来自路径与选股，
不是成本结构。本报告后续所有成本结论都以同集列（+0.026 / −0.014 / −0.013 / +0.007）为准。

### 1.3 成本本身有两个口径，1d 的"成本鲁棒化"在两个口径下都划不来

上面的 cost/R 来自**回测模型的保守口径**：`funding_per_8h_per_side = 0.0001`，
即**永远按持仓方向付费**。而真实资金费是多空之间的转移，收付相抵后可以变成收入。
`reports/live_cost_audit_20261023/FUNDING_REPLAY.md`（Binance 真实费率，1153 笔）实测：

| TF | 模型资金费/R | 真实资金费/R | 模型 E[R] | 真实资金费后 E[R] |
|---|---|---|---|---|
| 2h | 0.0121 | +0.0002 | +0.082 | +0.092 |
| 4h | 0.0193 | +0.0004 | +0.279 | +0.294 |
| 12h | 0.0340 | +0.0006 | −0.007 | **+0.021** |
| 1d | **0.0572** | **+0.0075**（收到） | +0.148 | **+0.198** |

1d 的模型成本 **0.074R** 里，**资金费 0.053R 占 72%**（净额扣减 = 手续费 + 资金费；
滑点已体现在 `gross_pnl` 的成交价里，不重复计），而真实口径下它是 **−0.0075R（收入）**
⇒ **"1d 被成本杀死"（1.5× 下 −0.016）主要是资金费模型造成的，不是真实世界的现象**：
真实口径下 1d 基线 1.0× 是 +0.198、1.5× 约 **+0.178**，从来没为负。

这对 1d 候选的含义（`Δnet(m) = −0.045 + m·Δcost`）：

| 成本口径 | 基线 cost/R | 候选 cost/R | Δcost | 盈亏平衡 m\* |
|---|---|---|---|---|
| 模型（保守，当前回测用） | 0.074 | 0.039 | 0.035 | **1.29×** |
| 真实资金费（审计） | ≈0.021 | ≈0.010 | ≈0.010 | **≈4.5×**（估算） |

⇒ **两个口径都不支持"现在上"**：保守口径要成本上行 29%，真实口径要上行 350%。
反过来说，**如果先修成本模型（资金费改成真实口径），1d 问题的前提就消失了，
也不需要这个候选**——这比调参更值得做。

## 2. 逐尺度判词

### 2h —— 没有可识别的改进；它是"成本机器"

- dev 从 +0.061 提到 +0.104，但 test 从 +0.008 掉到 +0.001，**差值全部落在 dev**；
- 它确实是唯一"毛利更高且成本更低"的格子（gross +0.118→+0.136、cost/R 0.074→0.068，
  同集差 @1.5× **+0.026**，见 §1.2），但增益全在 dev ⇒ 仍然不可用；
- **2h 的真正病灶是转化率：成本吃掉毛利的 62%**（1d 最优格是 19%）。同一份毛利，
  2h 要付出约 3 倍的成本，所以任何参数都只是在这个 62% 里挪动几个点；
- 入场闸**收紧**（rot3~4 / qual0.50 / imp1.2 / cd4，即现行档）已经把它的 N 压到 413，
  再压 N 只换到 WR 的小幅上升、E[R] 下降（见 `entry_2h.json` 的 119 格）。

**判词：保持现行。2h 的问题不是参数，是"成本吃掉 62% 毛利"。要动它只能动**
**持仓时长/换手（结构），不是动阈值。**

### 4h —— 现行参数已经是测试段最好的那一个；**禁止按 dev 调 4h**

- test 段基线 +0.468（n=109）是全表最高的单尺度表现；dev 最优格把它打到 +0.055；
- 全段 E[R] 完全持平（0.209 vs 0.208），但 payoff 从 2.27 涨到 3.09、WR 从 0.402 掉到 0.309
  —— 这正是"WR↔payoff 沿 PF 曲线滑动"的教科书例子：**净额没变，形状变了**；
- 机制：4h 的钱集中在 test 段的少数大趋势里，dev 段看不到它们 ⇒ dev 打分器自然会选
  "在 dev 上更稳、但会截断右尾"的几何。

**判词：保持现行。任何"用 dev 选出来"的 4h 改动都会打掉它约 0.4R 的 OOS 边缘。**

### 12h —— 入场闸不能提高 E[R]；出口改动只买到 WR，不买到钱

- 入场闸 48 格的结果：**do-nothing 就是 dev 最优**（+0.077）。收紧到 rot3 得
  WR 0.331→0.356、payoff 2.32→2.03、**E[R] 0.077→0.063**；再叠 imp1.2 直接掉到 −0.08；
- 出口侧 `stop 1.5 / target none / struct off` 把 dev 提到 +0.141，但 test 0.361→0.201、
  full 0.150→0.135 ⇒ **dev 与 test 严格反向**；
- 与 `MEMO.md §4.5` 的"A9 原始漂移 ≈ 0（20×TF no-stop −0.16 ATR）"一致：
  12h 的问题不在出场几何，在"没有可收割的漂移"。

**判词：保持现行；12h 的取舍只在"少做但 WR 略高"与"多做但 E[R] 略高"之间，
不是改进。若一定要动，只有"退休/降预算"这一类（减少参与），不是"调参"。**

### 1d —— 唯一一条能站住的路径：**用毛利换成本斜率**

- 基线 full@1.0 = +0.177；但 **cost/R = 0.074，即成本吃掉毛利的 30%**，
  所以 full@1.5x = −0.016（同集反事实 +0.140，见 §1.2）；
- 最优格 `rot0 / qual0.60 / imp0.0 / cd0` + `k_is 0.5 / stop 2.5 / target mid / struct off`：
  full@1.0 = +0.167（−0.010），**cost/R 0.074→0.039（成本只吃掉 19% 毛利）**，
  WR 0.383→**0.503**，payoff 2.21→1.77，N 128→147；
- **机制（逐项实测，§9 的 `--stage decomp`）**：`stop 2.5` + 关结构止损使每笔的
  **价格风险占比从 5.7% 升到 11.3%**，于是同样 2U 风险预算只买 **名义仓位 ÷ 风险
  从 17.6× 降到 8.9×**；手续费与资金费按 R 计因此**同步减半**：
  fees 0.0210→0.0107、funding 0.0532→0.0287（滑点已含在 gross 成交价里，0.0070→0.0036），
  持仓时长基本不变（258h→270h）。这是"成本鲁棒化"的**唯一**来源，与选币/择时无关；
- 代价：同样的价格波动折算成更小的 R ⇒ gross 0.251→0.206；`target mid` 使
  WR 升、payoff 降；
- 净效果是一条直线：`Δnet(m) = −0.045 + m × 0.035` ⇒ **盈亏平衡 m\* = 1.29×**，
  成本升到 1.5× 只领先 **+0.007R**，2.0× 时领先 +0.025R。
- 注意它**不是纯收紧**：`qual` 0.40→0.60 是收紧，但 `rot` 2→0、`cd` 2→0 是放开
  ⇒ 净效果是"只要箱体质量够高，就不限制旋转次数与冷却"（N 反而 +19）。

**判词：这是一个成本保险，不是改进——而且按真实资金费口径，这份保险的免赔额高到不值。**
保守口径（当前回测）下 m\* = 1.29×，真实资金费口径下 m\* ≈ 4.5×（§1.3）；
**成本模型本身才是那个该改的东西**。不要用 +0.171 这个数去争取立项——那是路径噪声。

## 3. 选择乐观度：为什么不能照着 dev 最优去改 config

每个 TF 的 119 格里，dev 打分前 10 名在 **test** 上的表现：

| TF | 基线 test | dev-top10 的 test 中位数 | dev-top10 的 test 最大值 | 结论 |
|---|---|---|---|---|
| 2h | +0.008 | +0.014 | +0.028 | 本来就没有边缘，谁上都一样 |
| 4h | **+0.468** | **+0.069** | +0.168 | 选择把 OOS 打掉 **−0.40R** |
| 12h | **+0.361** | +0.245 | +0.361 | 天花板就是基线本身 |
| 1d | +0.190 | +0.028 | +0.136 | 选择把 OOS 打掉 −0.16R |

**在两个真有边缘的尺度上（4h / 1d），"dev 选优"系统性降低 OOS；2h 上无差别（都 ≈ 0）；
12h 上搜索的最优结果就是"什么都不做"本身。** 这正是"参数面在 dev 上是平的、
在 test 上由少数大赢家决定"的典型形态 —— 与 `MEMO.md §0`"单笔 E[R] 的 CI 宽
±0.3~0.5R"完全一致。

**纪律结论：在这份样本上做 per-TF 调参，期望值是负的。**
（这也是历史上 B2 / A3 在两本书之间符号翻转的同一个机制。）

### 4.2 两段同时优于实际出场的规则只有 3 条，且幅度都在噪声内

## 5. 组合阶段：把"各自最优"合起来会发生什么

变体（全链，book4，`portfolio_cap_frac=0.12`，四尺度各持独立周期池 + 300U 复利；
跨尺度**不共享槽位**，见 §5.5）：

| 变体 | 说明 |
|---|---|
| `a0` | 现行 config（基线） |
| `best_all` | 四个尺度的 dev 最优格同时生效 |
| `best_2h4h` | 只改 2h + 4h（即"只看两本账都同向的尺度"） |
| `best_all_no12h` | 四格生效 + **移除 12h**（退休） |
| `best_all_cap_B` | 四格生效 + 预算重排 `12h 0.0075 / 4h 0.0375` |

### 5.1 E[R]（净，按风险归一）

| 变体 | dev@1.0 | test@1.0 | full@1.0 | full@1.5x | 全段净额@1.0 | DD% |
|---|---|---|---|---|---|---|
| `a0` | +0.066 | **+0.149** | +0.087 | +0.023 | +380 | 32.9 |
| `best_all` | +0.122 | +0.002 | +0.083 | +0.045 | +493 | 34.1 |
| `best_2h4h` | +0.130 | +0.047 | **+0.093** | +0.048 | **+515** | 37.8 |
| `best_all_no12h` | +0.154 | +0.025 | +0.090 | **+0.059** | +410 | **30.8** |
| `best_all_cap_B` | +0.146 | +0.032 | +0.092 | +0.049 | +412 | **29.4** |

test 段 CI（逐笔 bootstrap）：`a0` +0.149 [−0.038,+0.366]（n=462）；
`best_all` +0.002 [−0.142,+0.166]（n=486）；`best_2h4h` +0.047 [−0.121,+0.233]（n=456）。

### 5.2 先排除一个解释：叠加变差**不是**成本造成的

`best_all` 与 `a0` 在 test 段的成本几乎相同，崩掉的是毛利：

| 变体(test@1.0) | gross E[R] | cost/R | net E[R] | n |
|---|---|---|---|---|
| `a0` | **+0.232** | 0.102 | **+0.149** | 462 |
| `best_all` | **+0.079** | 0.096 | +0.002 | 486 |
| `best_2h4h` | +0.132 | 0.104 | +0.047 | 456 |

所以"四个最优拼起来最差"与成本无关，是**选股/毛利**问题：
四个格子在 test 段把 a0 最能赚钱的那批入场换掉了。

### 5.3 组合内逐尺度分解：ΔE[R] 其实**是可加的**

用 a0 的风险权重把"组合内逐尺度 E[R] 的变化"加权求和（`--stage decomp`）：

| TF | 权重(a0) | 组合内 test E[R] a0 → best_all | Δ | 对组合的贡献 |
|---|---|---|---|---|
| 2h | 48% | +0.015 → −0.023 | −0.038 | −0.018 |
| 4h | 24% | +0.393 → +0.011 | **−0.382** | **−0.092（占 62%）** |
| 12h | 19% | +0.252 → +0.078 | −0.174 | −0.033（22%） |
| 1d | 9% | −0.015 → −0.073 | −0.058 | −0.005（3%） |
| 合计 | 100% | **+0.149 → +0.002** | | **−0.148** |

- **可加预测 −0.150 vs 实测 −0.148**；`best_2h4h` 也是 −0.105 vs −0.102。
  ⇒ **组合里没有神秘的交互项，"最差"就是四个负项的加权和。**
- 每一项再拆成"格子本身(test 单尺度)"+"权益路径差"：
  4h = 格子 **−0.413** + 路径 +0.031；12h = 格子 −0.160 + 路径 −0.014；
  1d = 格子 −0.054 + 路径 −0.004。
  ⇒ **跌幅 ~93% 来自"格子本身在 test 上是负的"，只有 ~7% 来自共享账户**——
  且这 7% 不是"抢仓位"（`PORTFOLIO_CAP` = 0，见 §5.5），而是权益路径不同导致的
  逐笔风险权重不同（E[R] = Σnet/Σrisk 的加权效应）。

### 5.4 那么为什么四个格子"各自 dev 最优、合起来 test 为负"

1. **每一项都是选择偏差**：119 格里在 dev 上取最大，等于把"噪声的右尾"当成信号
   （§3 已量化：4h 的 dev-top10 在 test 上中位数只有 +0.069）。
   四个格子各自带一份 −0.05~−0.41 的 OOS 税，**加权和自然是 −0.148**。
2. **四份税不独立、不能互相抵**：它们都在同一个 dev 窗口、同一批币、同几个大赢家上
   选出来，错的是同一个方向（"抓住 dev 的那几笔"）。这不是四个独立下注，
   是同一个赌注下四份 —— 所以叠加不会把噪声平均掉，只会把偏差加满。
3. **还有方向性的一致**：四个格子里有三个放宽入场闸（`rot`/`cd`/`imp` 降到 0 或近 0），
   叠加后就是"同一方向加码"：dev 笔数 976→1012、test 462→486，
   每一笔的边际变薄（best_all 的 test gross 从 0.232 摊到 0.079）。
4. 反证：`best_2h4h`（只叠两个格）跌幅 −0.102、`best_all`（四个全叠）−0.148 ——
   **叠加得越多越差，且接近线性**，这正是"每一项独立为负"的特征，
   而不是"组合产生了额外损耗"。

### 5.5 "进共享账户被削 0.03~0.08R" 的正确解释：不是抢占，是权益加权

旧稿（和 `reports/tf_solo_20261023/RESULTS.md` §4/§9）把下面这些差额读成"共享 4 槽被挤掉"。
`--stage crowd` 用**同一批 a0 参数、只改"别的尺度在不在场"**把它测到了根（full 段，book4）：

| TF | 独占账户 n / E[R] | 四尺度共存 n / E[R] | 差额 | id 不重合(仅独占/仅共存) | 同笔 risk_usdt 偏差 |
|---|---|---|---|---|---|
| 2h | 629 / +0.0445 | 628 / +0.0359 | −0.0086 | 5 / 4 | 27.4% |
| 4h | 331 / +0.2088 | 333 / +0.1983 | −0.0105 | 2 / 4 | 32.2% |
| 12h | 348 / +0.1505 | 351 / +0.0967 | −0.0538 | 107 / 110 | 40.4% |
| 1d | 128 / +0.1771 | 128 / +0.0338 | −0.1433 | 35 / 35 | 50.2% |

**跨尺度抢槽不存在**，三条硬证据：

1. **账户池从不触发**：a0 共存 811 次 `cap_skips` 全是 `TF_CAP`，`PORTFOLIO_CAP` = **0**；
   `best_all` 的 970 次同样全是 `TF_CAP`。准入时刻 `admission_full_cost` 只返回周期池
   （`capacity.py` 的 `pools()`），账户池连参与准入都不参与；且 4×2.25% = 9% < 12%，
   本来也没有余量问题。
   > 口径提醒：`counters["portfolio_cap_skips"]` 这个键名计的是**全部**容量跳过（含 `TF_CAP`），
   > 不要被名字误导；区分池子只能看 `cap_skips[].reason_code`。
2. **槽位数不变**：并发峰值 13 个，**每尺度 4 个**；独占账户时每尺度**也是 4 个**。
   周期池 2.25% ÷ 单笔 0.75% ≈ 3 个名义槽，实测 4 个（价格靠近止损时最坏情景变小，能多放一个）。
   账户池 12% ÷ 0.75% ≈ 16 槽；即便把全部预算闸关掉（`loose`），峰值也只有 **15 个**——
   连账户池的容量都碰不到，这才是"抢占不可能发生"的结构原因。
3. **放开容量反而更差**：`loose`（周期池=账户池=100%，`cap_skips` = 0）n 1440→1643、
   net 380.1→334.7、E[R] **0.0875→0.0726**。容量闸不是"挤掉好单"，是在**每个 TF 内部做筛选**。

真正的耦合只有两条，**都不是抢占**：

- **共享权益 ⇒ 尺寸不同**：同一笔（symbol + 决策时刻 + 方向）在独占与共存下 `risk_usdt`
  差 27%~50%。E[R] 按风险加权，权重变了 E[R] 就变 ⇒ 上表 2h/4h 的 −0.01 基本是加权假象。
- **粒度**：权益水平不同 ⇒ 最小手数/步长取整不同 ⇒ `min_size_skips`（1d 独占就 43 次）与
  边际取舍不同 ⇒ 长尺度交易集在边缘漂移。长 TF 的周期池压制也最重（1d 129 次、12h 574 次
  `TF_CAP`），构成对权益最敏感。

**账户口径上四尺度几乎完全可加**：独占 net 之和 68.66+160.04+108.01+45.05 = **381.76**，
共存 **380.07**（−0.4%）。所以**单尺度净额不可相加**（1d 45.05→12.70、4h 160.04→201.05，
钱在尺度之间搬了家），**账户净额可加**。§5.3 的"挤占 +0.031/−0.014/−0.004"应读作
**权益路径差**；"~93% 来自格子本身"的结论不变。

真正被挤占的是**风险相关性**，不是槽位：同币跨尺度同时持仓占全部持仓时长的 **53.7%**
（1696 对、5.6 万 / 10.4 万交易小时；放开容量后 63.7%）。一次 4% 下跌会同时打掉 BTC 的
2h/4h/12h/1d 四个止损 = 4×0.75% = **3% 权益**。这才是"共用一个账户"的代价——体现在回撤与
相关性上，而不是"新信号进不来"。

## 6. 结论

### 第 1 问：每尺度最优路径

| TF | 该尺度最优路径 | 依据 |
|---|---|---|
| 2h | **= 现行参数**（无可识别改进） | dev +0.043 / test −0.007；成本吃掉 62% 毛利 |
| 4h | **= 现行参数** | dev 最优会把 test 从 +0.468 打到 +0.055 |
| 12h | **= 现行参数**（若动，只能"减少参与"） | 入场闸 do-nothing 最优；出口 dev/test 严格反向 |
| 1d | `rot0 / qual0.60 / cd0` + `k_is 0.5 / stop 2.5 / target mid / struct off` | cost/R 0.074→0.039，**盈亏平衡 m\*=1.29×**，1.0× 下 −0.010 |

**"让胜率、盈亏比、净 R 同时最优"在定义上不成立**（§0.3：WR 与 payoff 一经确定 PF 即定，
两者互为代价）。可选的只有"沿 PF 曲线往哪边滑"，而净 R 只认 E[R]。
按 E[R] 判定：**四个尺度里，三个的现行参数已经是最优；1d 的候选把成本吃掉毛利的比例
从 30% 压到 19%（盈亏平衡 m\*=1.29×），在现行成本下仍是 −0.010R。**
⇒ 结论是 **"都不要改"**；1d 那格只在"成本确认上行 ≥30%"时才作为保险启用，
且必须用同集反事实（+0.007R@1.5×）而不是实测的 +0.171R 去立项。
**更进一步（§1.3）**：1d 的成本 66% 是模型资金费，真实费率审计下该项是收入 ⇒
真实口径下 1d 从未被成本杀死、m\* ≈ 4.5×。⇒ **优先级最高的一件事是修成本模型
（资金费改真实费率），而不是动任何 per-TF 参数。**

### 第 2 问：最优组合

- **1.0× 成本（现行）：`a0` 就是最优组合**（test E[R] +0.149，全段 +0.087，DD 32.9%）。
  任何"优化组合"都不可区分或更差（+0.002 ~ +0.047）。
- **1.5× 压力档：`best_all_no12h`**（full +0.059 / 净额 +225 / DD 30.8%），
  次优 `best_all_cap_B`（+0.049 / +175 / DD 29.4%）。这两个变体的优势来自
  "参与更少 + 1d 那格的成本斜率"，不是 alpha；且 1.5× 下 12h/1d 的交易集会变（§1.2）。
- **`best_all`（四个 dev 最优直接拼）是最差组合，原因是纯算术的**：
  四个格子在 test 段各自为负（−0.008 / −0.413 / −0.160 / −0.054），
  按风险权重相加就是 −0.148（预测 −0.150 / 实测 −0.148）；其中 4h 一项占 62%。
  **不是"组合产生了额外损耗"，而是"每一项本身就是负的"**（§5.3–5.4）。
- **可操作结论**：per-TF 调参在 dev 上的增益不能转化为组合收益；组合评估必须
  在同一份 dev/test 切分上一次性联合判定，不能"各自调好再相加"。

## 7. 与既有结论/待决事项的关系

1. **支持 `MEMO.md §4.5` 的 12h 判词**：12h 的入场闸搜不出 E[R]，出口叠加上限 ≤ 0，

2. **"加宽止损"再次被否**：4h 的 dev 最优确实选了 `stop 2.5`，但它的收益来自 dev 段，

3. **`prereg/20261023_per_tf_policy.md` 的 P1 若照注册跑，会不过自己的门**：

4. **`P3`（1d 限价入场）与本次 1d 结论不冲突**：本次的 1d 改进是"提高质量分 + 收紧目标"，
   与"限价入场"是两条正交的路；但两者都必须在同一份 prereg 里定判定门，不能叠加着算。
5. **2026-10-23 收口：全部未决问题已汇总到 `reports/BACKLOG_20261023.md`**
   （按阻塞关系排 P0/P1/P2/P3 + 已证伪清单）。本报告 §6 的两条"都不要改"结论**仍然成立**，
   但其中"1d 是成本问题"的理由已被真实资金费口径抽掉（真实 1d 资金费是**收入**，
   `m*≈4.5×`）⇒ 1d 不应再以"降成本"为由立项，只保留为"成本上行 ≥30% 时的保险"。

## 8. 局限（必须与结论一起读）

- **单尺度 = 该 TF 独占 300U 与全部预算**，不是"同一批交易换个尺寸"；账户路径不同，
  `risk_usdt` 因此不同，所以横向比较只用 E[R]（按风险归一），不用绝对净额。
- **"最优"= 119 格网格 + dev 打分**。网格之外（如 `min_box_rr` 上界、`max_target_r`、
  按持仓时长计费的预算）没有测；其中"目标距离上限"目前**在 config 里不可表达**
  （只有 `min_box_rr` 下限），要做得改 src。
- **test 只解封用于报告**，但 4h/12h 的 test 段已经被历史上多轮实验间接接触过，
  不是 virgin；真正的 virgin 只有 DOGE 与未来数据。
- **成本档横比会被"换了一批交易"污染**（§1.2）：12h/1d 的 1.0× ↔ 1.5× 重叠只有 83–97%，
  1d 的 11 笔非交集交易几乎贡献了全部毛利。任何"1.0× vs 1.5×"的结论都必须配同集反事实，
  否则会把路径噪声当成成本效应（本报告初稿就犯过这个错）。
- **同集反事实假设成本对 m 线性**（费率/滑点/资金费都是乘子）。若真实成本含固定最低
  手续费、阶梯返佣或冲击成本，这个线性外推会偏乐观。
- E[R] 的 CI 宽 ±0.2~0.6R：**本报告能证明的是"没有可识别的改进"，不是"改进不存在"**。
- 出场叠加屏用的是 `abcd_20261022` 账本（BTC/ETH/SOL），与 5.x 的生产账本（+DOGE）
  不是同一批交易；它只用于方向判定。
