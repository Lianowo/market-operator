## 一、AMT 第一性原理演进与消融验证（Ablation Study）

本系统坚持**零滞后均线/振荡指标、纯价格结构与价值区拍卖边界**的第一性原理架构。在本轮改进中，我们对每一项规则进行了逐项前向消融验证（仅保留在多批次样本外均取得净正收益且降低回撤的机制）：

### 1.1 已验证并合入主干的核心机制
1. **趋势破位防御护栏（`STRUCTURE_BROKEN` / `E6` Router Defense，`src/market_operator/routing.py`）**
   - **第一性原理**：当认知周期 K 线收盘击穿关键结构拐点并发射 `STRUCTURE_BROKEN`（`E6`）时，说明原方向的市场拍卖结构已被证伪。
   - **机制**：在 `MarketRouter.on_bar` 中，一旦当根出现 `STRUCTURE_BROKEN`，立即撤除同战役未成交的入场挂单（`e6_cancel_orders`），并拦截同一根 K 线上与该破位方向相反的任何逆势入场信号（`restraint_e6_reverse_defense_reject`）。
2. **角色互换回踩二次起爆（`FLIPPED_BOX_EDGE` `LEVEL_REJECTED` Trend Continuation，`src/market_operator/routing.py` & `config/strategy.json`）**
   - **第一性原理**：平衡箱体被放量突破后，原箱体边界发生支撑/阻力角色互换（`FLIPPED_BOX_EDGE`）。当价格在顺应大趋势（非逆势）的前提下回踩该翻转边界，并在 **`>= 4h` 大周期认知收盘**形成带扫损长影线的拒绝确认（`R1_WICK`）时，属于经典的 **Break-and-Retest（破位回踩确认二次起爆）**，而非箱内均值回归。
   - **机制**：放行 `>= 4h` 认知收盘上的 `FLIPPED_BOX_EDGE` + `R1_WICK` 顺势回踩确认，目标位采用箱体等幅扩展（`accept_target_box_mult = 2.0`），并标记 `trade_context = "回踩确认"`。
3. **大周期由平衡转失衡的箱外真突破放行（`>= 4h` `BOX_EDGE` `BREAKOUT_ACCEPTED` from `Regime.RANGE`）**
   - **第一性原理**：拍卖市场由平衡（Balance / `RANGE`）向失衡（Imbalance / `TREND`）演进的第一棒必然始于 `Regime.RANGE`。小周期（`< 4h` 或 `mic=True`）在震荡箱体中的向外突破噪音极高，应予拦截；但 **`>= 4h` 大周期认知收盘**完成的 `n_a=3` 根箱外驻留确认，代表机构级拍卖共识向箱外迁移，予以放行。
4. **80% 法则价值区重返入箱的精准解绑（`FLIPPED_BOX_EDGE` `A1_TIGHT` Re-Entry）**
   - **第一性原理**：当价格突破箱体失败并重新收复翻转边界回到原价值区内部（`FLIPPED_BOX_EDGE` 上的 `BREAKOUT_ACCEPTED`，即 AMT 80% 法则重返入箱），紧贴箱沿内侧收盘（`A1_TIGHT`）代表最佳盈亏比位置（止损在箱沿外侧，目标看箱体对侧 `box_opposite`）。
   - **机制**：将认知收盘 `A1_TIGHT` 的过滤严格限定在 `sk_align == "BOX_EDGE"`（向外突破），不再误杀 `FLIPPED_BOX_EDGE`（向内重返价值区），单此一项在 30 品种上救回 52 笔高盈亏比交易、净增 `+11.52R`。

### 1.2 经实证证伪并果断丢弃的假设（防止负优化）
- **在 `< 4h`（`2h` / `mic`）上放开 `FLIPPED_BOX_EDGE` 回踩拒绝**：实测在 30 品种上产生 132 笔交易，胜率仅 `30.3%`，净亏损 `-17.48R`（短周期回踩假信号过多），故严格锁定在 `>= 4h` 认知收盘。
- **`R1_WICK` 强制要求实体与前根反向**：实测误杀了高动量 V 型扫损反转阳/阴线，导致总收益下降 `-8.35R`，已回退。

## 三、容量抢占与 `TF_CAP` 硬拒绝死锁的根因及动态仓位分配机制

### 3.1 两大根因诊断
1. **根因一：`admission_full_cost` 下“第 3 槽位必死”的算术死锁**
   - 系统配置单笔风险 `5%`（固定风险 `0.75%`），单周期容量上限 `tf_cap = 15%`（固定风险 `2.25%`），设计意图是每个周期允许同时持仓 **3 笔**标准仓位（`3 × 5% = 15%`）。
   - 但 `admission_full_cost` 在准入计算 `delta_exposure` 时，在止损金额之外叠加了双边开平手续费与滑点（约 `0.4% ~ 0.8%` 权益），导致单笔 `5%` 交易实际消耗约 `5.5% ~ 5.8%` 预算。
   - 当某周期已有 **2 笔**持仓（占用约 `11.2%`）时，池中明明还剩 **`3.8%` 的可用风险额度（足以开出约 70% 的标准仓位）**，但第 3 笔交易按 `1.0x` 满额申请（需 `5.6%`）时触发 `11.2% + 5.6% = 16.8% > 15.0%`。原代码采取“一刀切整笔硬跳过”，导致**每个周期的第 3 笔信号被 100% 强硬拒单**。
   - 此外，`src/market_operator/campaign.py` 第 1063 行在决策门计算 `qty_full` 时漏传了 `d.meta["size_mult"]`，导致即便策略层下调了 `size_mult`，准入门仍按 `1.0x` 满额卡死。
2. **根因二：快时间尺度（`2h`）全额抢占慢时间尺度（`4h`）的主张预算与名义杠杆**
   - 在 35 品种实测中，`4h` 周期的单笔期望（`+0.343R`，胜率 `49.9%`）是 `2h` 周期（`+0.126R`，胜率 `39.8%`）的 **2.72 倍**，而 `2h` 因止损更窄，单笔消耗的名义杠杆反而是 `4h` 的 **1.43 倍**。
   - 当 `2h` 认知收盘上的 `FLIPPED_BOX_EDGE` `A1_TIGHT` 重返单按 `1.0x` 满仓入场时，会抢先占满同标的跨周期共享的 `CLAIM_CAP`（`15%`）及账户 `20x` 总杠杆，把随后到来的 `4h` 主升浪信号挤出局。

### 3.2 解决方案与实测提升
我们在 `src/market_operator/routing.py`、`src/market_operator/campaign.py` 与 `scripts/live_runner.py` 中统一实施了两层动态仓位分配：
1. **快周期（`< 4h`）`FLIPPED_BOX_EDGE` `A1_TIGHT` 半仓分配（`size_mult = 0.5`）**：不丢弃任何 `2h` 有效信号，但将其权重设为 `0.5x`，为 `4h` / `1d` 主周期留出预算与杠杆余量。
2. **剩余额度动态缩量准入（Soft Headroom Scaling，`min_alloc_frac = 0.25`）**：当 `delta > eff_headroom` 时，只要剩余可用额度 `scale = (eff_headroom * 0.999) / delta >= 0.25` 且缩量后满足 `min_trade_usdt` 与 `size_min`，自动将 `size_mult` 缩量至剩余额度入场，彻底消除“第 3 槽位死锁”。

| :--- | :---: | :---: | :---: |
| **25 品种 · 阶梯复利** | `87,108 U` (`174.2x`), `Sum_R=+159.41R`, `skips=95` | **`137,450.44 U` (`274.9x`)**, `Sum_R=+180.59R`, `skips=42` | **`+50,342 U` (`+21.18R`)** |

## 四、实盘 `NILUSDT` 止损异动（`0.06304 -> 0.08177`）根因溯源与五重加固

### 4.1 事故完整还原（基于 `logs/live_20261107.jsonl`）
- **现象**：`NILUSDT` `4h` 空单（入场价 `0.06097`，结构失效止损应为 `0.06304`），在交易所上的止损触发价被改成了 `0.08177`。
- **根因链条**：
  1. 当时机器上意外同时运行了两个 `live_runner.py` 进程，在同一秒对 `NILUSDT` 发起开仓，生成了相同的幂等 `clientOid`。
  2. 进程 A 下单成功（`0.06097` 成交，挂出 `0.06304` 止损）；进程 B 晚到几百毫秒，收到 Bitget `code=40786`（`Duplicate clientOid`）。
  3. 旧版 `bitget_live.py` 将 `40786` 当作普通异常重试 3 次后抛出 `BitgetError`，进程 B 将本地 `open_intents` 中的该笔意图标记为 `status="error"`。
  4. 紧接着进程 B 执行 `_reconcile()` 对账，发现交易所上有 `NILUSDT` 空仓，但本地因状态为 `"error"` 而未关联成功，遂调用 `_adopt_exchange_only()` 将这笔本属于策略自己的 `4h` 仓位误判为“外部手工仓位（`ADOPTED`，默认归入 `1d` 日线周期）”，按 `entry + 2.0 × ATR_1d = 0.08177` 重新挂出了宽止损，覆盖了原有的 `0.06304` 止损！

### 4.2 已落地的五重工程防线（`scripts/live_runner.py` & `src/market_operator/bitget_live.py`）
1. **OS 级进程单实例互斥锁（`SingletonLock`）**：在 `live_runner.py` 启动入口强制获取 `runtime/live/runner.lock`（Windows `msvcrt.locking` / POSIX `fcntl.flock`），从物理上杜绝两个 `live_runner` 实例同时运行。
2. **Bitget 确定性业务错误码快速失败（Fast-Fail）**：在 `bitget_live.py` 中新增 `_NON_RETRIABLE_BIZ_CODES = {"40786", "22002", "43023", "40808", "45110"}`，遇到业务拒绝码立即抛出，不再无意义盲目重试。
3. **`40786`（重复 `clientOid`）幂等恢复**：`_submit_open` 捕获 `40786` 时，直接保持 `it["status"] = "armed"` 并触发 `_reconcile()` 认领已成交仓位，绝不误标为 `"error"`。
4. **`_adopt_exchange_only` 自有历史意图优先认领**：在走 `1d` 兜底收养前，优先匹配 `open_intents` 中同品种、同方向的近期自有开仓意图（包括 `"error"` / `"armed"` / `"filled"`），直接恢复原周期 `tf_label`、`invalid`（止损价）与 `target_1`（目标价）。
5. **`_manage_stops` 交易所远端 `triggerPrice` 双向强校验**：每次巡检不仅核对 `orderId` 是否存在，还比对交易所计划单的真实 `triggerPrice` 与本地 `cur["trigger"]` 是否一致，一旦偏离超过 `1.5` 个 tick 立即撤旧换新。
