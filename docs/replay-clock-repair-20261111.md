# 回放真实时钟与跨标的阶段屏障修复

## 原因与范围

旧循环将执行K线和触发K线的开盘标签当作同一个事件时间。整根1h的
止损/挂单/收盘盯市可能在同标签30m信号之前处理；粗于执行帧的MIC也
可能提前推进。逐标的从开盘到收盘完整处理又让后面的标的开盘看到前面
标的的收盘状态。`fill_ts > decision_ts`只是标签检查，不能排除上述泄漏。

修复只改执行基础设施，不调整信号规则、风险比例、标的名单或成本参数。
生产装配默认使用不慢于最细信号的共享执行网格；本轮为本地原生30m。
不能在1h区间尚未结束时让30m决策撤销可能已成交的旧挂单，因此旧1h执行
加30m触发的组合现在明确拒绝，不以“延后成交”掩盖中途撤单的不确定性。
历史结果精确复现不再作为修复的验收要求，因为旧结果可能受缺陷影响。

## 修复契约

1. 全局事件时间集合包含每根执行K线的开盘、真实收盘，以及MIC真实收盘。
2. 同时刻先处理全部已结束执行区间的原有保护单/限价单，包含新限价入场
   当根触及止损时的保守不利路径；本收盘新提交的订单不得回到该区间。
3. 批量更新全部结束区间的收盘价、资金费，然后做组合强平检查。重复的
   待强平意图不重复提交。
4. 推进已收盘执行帧持仓管理、完整认知帧、MIC。MIC只负责决策，不再
   把自己的粗OHLC当成另一套执行路径重复撮合。
5. 同步全部下一执行开盘报价，再按确定性的战役键FIFO撮合两类待成交单。
   开盘报价更新本身不再次计提资金费、不额外生成同开盘强平意图。
6. 所有新市价/限价意图携带真实可执行下界。执行步长必须整除触发步长；
   限价只能参与开盘不早于其信号收盘的执行区间。
7. 持仓管理在执行帧收盘产生的目标挂单使用执行帧真实收盘，而不是错误地
   再等待一个认知周期。末端不完整认知桶不得提前公开缓存的完整认知。
8. 权益行标记真实收盘事件时间，包含末根执行K线收盘，而非旧开盘标签。

## 剩余明确限制

- OHLC不能恢复同根真实价格路径；保留既有不利止损假设和严格穿越规则。
- 同一时刻多笔争用容量依然有明确的键FIFO优先级，非名称置换不变保证。
- 限价/止损日志仍以所在执行区间的开盘标签表示成交所在K线，不声称精确
  tick成交时刻。状态只在该区间结束后对后续决策公开。
- 同期区间内多标的成交的精确先后未知，按上述FIFO模拟，不等价于逐笔撮合。
- 执行网格由旧1h改为原生30m，因此收益差异包含时钟与执行粒度两项修正，
  不是纯排序实验。依然不等价于真实延迟/流动性；缺必要细数据直接失败。
