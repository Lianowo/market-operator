# 实盘价格保护执行（2026-11-10）

## 边界

只修改实盘接入与保护配置，不修改 strategy.json、事件、路由、入场、目标计算、
50% 首次减仓、保本开关或峰值回吐预算公式。生产 protection.price_clock=realtime。
bar / 15m 兼容路径保留。正 frac 的触及规则用新鲜报价即时观察，负 frac 不改成触及规则。

## 执行顺序

1. 市价、限价及 Watch 入场请求携带 presetStopLossPrice，触发后市价止损。
2. 注册持仓后，在图表/通知之前建立或复用交易所仓位止损，并立即提交原目标的
   profit_plan 定量止盈（当前生产规则：原数量 50%，fill_price 触发、市价执行）。
   开仓接口预设止盈无法独立指定半仓数量，因此没有把半仓策略改成整仓止盈：
   半仓止盈是建仓后的第二次请求，不宣称与开仓原子提交。
3. 每轮先同步止盈事实并观察新鲜报价，再进行慢速宇宙/历史工作。
   原目标触及即武装，随后按现有峰值回吐预算收紧防线，修改原止损单，避免主动撤旧失保。
4. 半仓止盈挂出后 pending_reduce 防止策略 bar 或本地报价重复消费减仓额度；
   orders-plan-history 的 executeOrderId 加上成交回执证明成交后才更新数量与保本，
   支持累计分笔成交及幂等入账。挂单消失本身不是成交证据。
5. 价格来源未知不再关闭 realtime 保护；真实成交均价回执仍独立校正记账。
   假定开仓参考价只用于临时记账，不能声称为已核实的成交价。

## 恢复与限制

- 使用确定性 clientOid 恢复挂单；明确未执行的撤销/失败可换新代号重挂。
- 修改止损失败保留旧保护并告警；定量止盈拒绝则告警，实时触价继续走原减仓规则。
- 交易所执行固定目标与固定止损不依赖 15m bar 或本地进程在线。
- 峰值追踪仍是 REST 报价轮询（配置 poll_seconds=5），不是 WebSocket，不能保证捕获
  两次采样之间的最高/最低价；网络、交易所拒单、滑点及主循环耗时也会影响实际保护。
- 只改文件不会更新已运行进程；未自动重启实盘、补挂现有仓保护或改写 runtime 状态。
  启用前应检查账户模式、交易所回执和现有保护订单，不能把离线测试当成线上挂单成功。
