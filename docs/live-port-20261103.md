回放链与实盘链是两套接线。本文件逐条说明：哪些语义修正已经**同时**落到
`scripts/live_runner.py`，落点在哪，以及哪些是回放专属（不影响实盘）。

## 2. 落点细节

### C1 定仓基准

```python
self.unrealized_pl = float(bal.get("unrealized_pl") or 0.0)   # _step_inner
capital = max(0.0, equity - float(self.unrealized_pl or 0.0))  # _submit_open
qty = eff_rf * size_mult * capital / risk_per_unit
qty = min(qty, eff_lev * equity / entry_ref)                   # 杠杆仍用权益
```

为什么不是直接用 `equity`：浮盈能撑保证金（偿付能力），但不是已经拥有的本金。
回放里同一口径已实测：DD 51.63% → 44.57%。

### C2/C5 主张预算

```python
group = sum(worst_case_of_position(...) for key, p in self.positions.items()
            if key.split("@")[0] == sym and p["direction"] == hyp.direction)
if group + candidate > float(tf_cap) * capital: block = "CLAIM_CAP"
```

周期是观察尺度，不是账户：同一标的同一方向的 2h/4h/12h/1d 仓位共用一份额度。

### C3 相反主张

```python
if any(p["direction"] == -hyp.direction for key, p in self.positions.items()
       if key.split("@")[0] == sym): block = "OPPOSITE_CLAIM"
```

净敞口为零，却付两份成本、占两份预算、等两个相反的止损——那不是两个判断。

### C4 完成即重定基

实盘与回放共用 `opp_lock_step`；差别只在"什么时候算完成"：
回放过去要求收盘越过目标，实盘现在与回放一起改成**触价即完成**，随即把防线
从"出发时的结构止损"换成"峰值锚定的回吐预算"。

## 3. 明确没有同步的

- **C5 身份/几何版本**：实盘不消费 `claim_id`；接它需要仓位与结构快照的对应关系，
  在 S4（跨 campaign 命名空间）解决前不接，避免伪碰撞。
- **C6 有效期强制**：实验否证（退役组平均 R 0.694 > 存活组 0.196），**不接**。
- **百分比回撤治理**：已证明与仓位规模无关，不通过缩仓处理。

## 4. 风险与已知缺口

- 实盘 `capital` 用"权益 − 未实现盈亏"近似"已落袋现金"；交易所口径与回放的
  `cash` 不会逐分相等，但方向一致（浮盈不计入本金）。这是**近似**，不是恒等。
- `CLAIM_CAP`/`OPPOSITE_CLAIM` 目前在 `_submit_open` 内联实现，尚无独立单测；
  与回放的 `claim_headroom()` 是两份代码、同一语义——**这是下一个该消除的重复**。
- 实盘未保存 `claim_id` 到仓位；C6 类诊断在实盘不可用。

## 5. 结论

实盘的**风险分配语义**已与回放对齐（C1/C2/C3/C4）；身份与有效期按研究结论不接。
收益验收仍以回放为准，实盘不宣称任何收益改进。
