# Telegram 通知准确性修正（2026-10-30）

## 范围与纪律

- 不改events/routing/trigger/position/broker/campaign策略核心。
- Watch仍由系统监控；建立关注时不向交易所挂限价单，触发后沿既有检查及市价下单路径执行。
- 公开信号只说明结构与执行计划，不宣称成交，不公开实际账户风险档位。
- 运营通道接收关注建立、触发委托、作废/到期、开平仓、防线推进、日结及告警。
- 未配置独立运营通道时仍保留既有回退行为；此次不读取凭证、不连接Telegram或交易所、不重启生产。

## 修正

1. 下单前信号从“已开仓/已挂单”改为“计划提交”，Watch明确“尚未下单”。
2. Watch展示关注价、近价企稳区、行情走完作废价及等待期限（均来自既有路由元数据）。被容量挡下的信号仍能广播，但不宣称关注已建立。
3. Watch生命周期通知仅在既有状态变化后附加，不参与触发判定/订单/账本。
4. 实盘市价参考价暂记明确标注“待成交回执”，不冒充已核验成交均价。
5. 防线推进展示持仓数量/参考价；平仓图方向采用原持仓方向，而不是平仓订单方向。
6. 实现盈亏展示为本次平仓估算口径，不宣称整笔扣全成本净利润。
7. REJECT显示“边界拒绝”，不再只表述为刺穿拒绝。
8. 图片说明超过caption限制时，工作线程发送完整配套文字及图片，避免Watch条件被截掉。
9. NotificationGuard隔离非信号send方法的模板/发送异常；信号保持原独立错误计数，错误日志写入失败也不得阻断交易。

## 隔离验证

- 生产入口保持async_mode=True：网络请求和图片渲染在通知工作线程执行；不引入同步等待。
- 队列满直接丢弃并计数，不等待，不阻止下单。
- 假通知器抛错时，对照市场订单、持仓、意图、待成交校正记录及交易计数保持一致。
- 关注到期通知失败仍完成到期状态与计数；平仓通知失败仍完成持仓清理。
- 不能声称“绝对零耗时”：模板字符串构造及入队仍有有限本地开销；通知共享进程资源，异步并不是操作系统级资源隔离。

## 同步风险配置

已确认五档：≤1000为5%；≤5000为4%；≤10000为3%；≤50000为2%；≤10亿为1%。
live.json的备用risk_frac改为0.05；strategy.json只修改small_account_compounding的档位，顶层常规回测risk_frac=0.0075保留。
该新五档没有在本次通知修正中重跑收益回测，不能套用之前三档回撤预算候选的结果。
