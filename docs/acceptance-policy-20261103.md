# 验收政策：把"正确性"和"结果"分开（2026-11-03）

## 0. 为什么需要这份政策

`tools/replay_acceptance.py:compare()` 的规则是"**任何一个切片都不许比基线差**"，
且切片之间不能互相抵消。它回答的是"**有没有任何一处退步**"，
**不是**"这次改动在语义上是否成立"。

用"零退步"去门"语义修正"，会系统性否决一切结构性改动——因为任何规则变化都会
改变某些桶的构成。这不是它算错了，是**用错了地方**。

同时，"语义正确 ⇒ 结果可接受"也不成立：语义正确 ≠ 结果无害。
所以验收必须分层，且**阈值必须事前声明**。

## 1. 三层验收

### 第 1 层：正确性门（二进制，一票否决）

必须全绿，任何一项失败即拒绝：

| 类别 | 判据 |
|---|---|
| 语义不变量 | 单元测试：主张身份/预算/相反主张/完成语义/证据完整性 |
| 回放不变量 | 无强平（`liquidations == 0`）、无负现金、成交严格晚于决策、无相反方向并存、预算不超限 |
| 账本对账 | 权益 = 现金 + 未实现 − 未结资金费；现金变动 = Σ(已实现 − 费用 + 资金费) |

这些是**语义是否被实现**的证明，与收益无关。

### 第 2 层：结果预算（事前声明，逐场景）

针对每个场景（severity × cost multiplier）：

1. **净收益**不低于基线；
2. **最大回撤**不高于基线。

任一项不满足即拒绝。注意口径：净收益用"段内已平仓净额"，回撤用完整盯市路径，
两者不可混用。

### 第 3 层：分布审查（不单独否决，但必须解释）

允许个别切片变薄，条件是三条同时成立：

1. **没有切片由正转负**（`+ → −` 是性质变化，`+ → 更小的 +` 是分布代价）；
2. 每个退步切片都能追溯到**一条具体规则**的代价（逐笔证据），不是"运气"或"路径"这种笼统说法；
3. 退步幅度不超过该切片基线贡献的**事前声明比例**（本次会话未声明，见 §3）。

## 2. 什么事前声明、什么算事后

- 阈值、比例、判定维度必须在**跑之前**写进本文件或工单；
- 若在看过结果之后才补阈值，必须标注 `post-hoc`，并在**新样本**（walk-forward 或未来数据）上复核；
- **不允许**为了让结果变绿而修改第 1 层或第 2 层。

### 结论

**语义修正准予合并；"零退步"不作为语义修正的否决门。**
`compare()` 保留为**诊断工具**（在纯收益优化阶段仍有价值），不再作为语义改动的验收门。

## 4. 仍然一票否决的情形

- 任何第 1 层不变量失败；
- 任一场景净收益低于基线或回撤高于基线；
- 任何切片由正转负（无论金额大小）；
- 退步无法归因到具体规则。

## 5. 已知局限

- 基线是同一段历史的自身冻结，不是外部基准；
- dev/test 已被反复查看，**不构成样本外**；
- 净收益口径不区分风险、持仓时长与资金规模；
- 本政策不替代"策略是否值得上线"的产品判断，只规定"改动是否可以合并"。
